# 0006 — Authentication topology

**Status:** accepted (2026-06-27)

## Decision

**App-native auth.** Windmill has its own login/user system (verified: default-cred login returns a
superadmin bearer token). So:

- **No `proxyAuth`.** Walling the app with Cloudron SSO would 302-redirect every webhook/API/SDK
  client to a login page and break all programmatic use (field guide §6). Windmill's webhook and API
  surfaces must stay reachable and are protected by Windmill's own tokens.
- **`optionalSso: true`** in the manifest — the operator may run without Cloudron user management.
- **Default superadmin** `admin@windmill.dev` / `changeme`. Windmill seeds this in a migration with a
  fixed hash; there is **no env var to pre-seed a random password**. So "change it immediately" is a
  manifest `checklist` item and the first line of `POSTINSTALL.md`. (A first-boot API-driven password
  reset was considered but rejected for v1 as racy/fragile; revisit later.)

## OIDC / Cloudron SSO auto-wiring — deferred (stretch)

Windmill can consume OIDC, and Cloudron's `oidc` addon injects `CLOUDRON_OIDC_*`. Auto-wiring it
(mapping those into Windmill's instance OAuth config on boot, with the manifest
`oidc.loginRedirectUri`) is a future enhancement. Deferred because Cloudron's SSO type is fixed at
install time and the wiring needs its own robustness pass. v1 ships app-native; operators can
configure OAuth/OIDC manually in Windmill instance settings.

## Consequences

- Webhooks, the REST API, and language SDK clients work without an SSO redirect.
- Operators are responsible for changing the default password and configuring any external IdP.
